# MC整合包软件使用流程及使用说明

该模块介绍了软件中每个部分的使用流程和使用说明。

# 版本迁移器
## 使用流程
1. 选择并读取原整合包。
2. 确认目标 Minecraft、加载器类型和加载器版本。
3. 输出文件名会根据源包名称和目标 Minecraft 自动生成。例如源包为 `1.21.1 录制.zip`、目标版本为 `1.21.11` 时，名称会变为 `1.21.11 录制`。目标版本继续变化时，自动名称会同步更新；用户手动修改名称后，软件不会覆盖自定义内容。同版本迁移会添加“（迁移）”后缀，并禁止输出路径覆盖原包。
4. 点击“检查兼容性”。工具会先用原平台项目 ID、ForgeCDN fileID 和文件哈希确认身份；只有没有精确身份的条目才会使用文本搜索。Modrinth 文本搜索未命中时会自动回退 CurseForge，并依据平台清单检查可识别的直接依赖与明确冲突。
5. 兼容性检查完成后，“生成新整合包”按钮即可点击。若有项目没有目标版本，工具会询问是否从输出中排除。
6. 选择“是”会排除该项目并重新分析；选择“否”只会忽略本次提示，不会排除项目，也不会把未经验证的旧版本当作目标版本保留。
7. 点击生成时，仍未处理的无目标版本项目会再次询问。若继续选择“否”，本次不会导出整合包；只有排除这些项目并通过重新分析后才能生成。
8. “可能缺少必需前置模组”仅作为兼容性风险提示。工具不会自动查询、添加、恢复或启用任何模组，此提示本身不会阻止生成，是否调整列表由用户自行判断。
9. 用户实际排除项目后，工具会重新运行兼容性分析。原始整合包始终不会被修改。

## 使用说明
导出完成后会明确提示：整合包可能仍存在部分模组及前置版本冲突或不符合。该提示用于说明静态平台清单检查的能力边界，不代表导出失败。

“构建完整包并嵌入可下载文件”会尝试下载并校验文件。若下载失败但目标格式允许远程引用，工具会回退为联网安装引用，并在完成提示中明确列出；无法引用也无法嵌入的文件会列为未包含。

工具保留源包格式：CurseForge 输入仍输出 CurseForge，Modrinth 输入仍输出 Modrinth，不负责两种格式互转。

目标 Minecraft 与加载器类型和原包相同时，工具不会调用平台搜索，也不会重新挑选文件；清单中的 `files` 条目会逐字段原样写回。加载器运行时版本可以更新，但这不会触发模组文件重匹配。该模式优先保证“同环境重打包”不发生项目漂移。

原包 `overrides` 中的所有现成内容均不属于查询和迁移范围。工具不会查询这些内容的平台信息，不会迁移版本，不会改名、删除或覆盖文件；构建新包时会保持原相对路径和原文件内容，原样打包。

## 兼容性检查范围
- 兼容性报告只检查 manifest/index 中记录的模组、资源包和光影包。
- 检查目标 Minecraft / 加载器版本是否存在匹配文件，以及重复项目和重复输出路径。
- 对模组检查可识别的必需依赖和平台明确声明的冲突。
- 构建完整包并实际下载文件时，校验目标文件大小及 SHA1 / SHA512 等可用哈希。
- Modrinth `files[].env` 客户端/服务端规则会写回远程引用。完整包模式遇到有作用域的文件时会保留联网引用；必须嵌入但无法安全保留作用域时会阻断。
归档读写仍会执行独立的安全校验，包括 ZIP 路径、重复路径、条目数量、解压大小和异常压缩比；这些校验不属于内容兼容性分析。




# 服务端一键打包

## 使用流程

1. 在“文件夹”和“整合包”之间选择导入方式。文件夹模式请选择 Minecraft 游戏目录或版本隔离实例；整合包模式支持选择或拖入标准 CurseForge `.zip`、Modrinth `.mrpack`。
2. 点击“读取内容”。若所选 `.minecraft` 目录没有可读取的 `mods`、`config`、`saves` 等内容，工具会提示重新选择 `.minecraft\versions\对应版本`。若检测到多个标准版本 JSON，会弹窗让用户选择。
3. 工具读取 Minecraft 版本、加载器及加载器版本。以上信息均由导入内容决定，**不可修改，也不提供版本迁移**。服务端打包目前不支持 Quilt。
4. 整合包模式只读取模组下载项，并读取 `overrides` 或 `server-overrides` 中的 `mods`、`config`、`defaultconfigs`、`kubejs`、`scripts` 和 `saves`。材质包及光影包下载项不会加入服务端。
5. 工具会将模组分类为“推荐”“可选”“不支持服务端”或“未知”。推荐模组、无法查到公开信息的本地模组及明确的必需前置默认勾选；可选模组、客户端专用模组和被禁用模组默认不勾选。
6. 根据需要调整模组，选择是否导出 `config`、`defaultconfigs`、KubeJS 和脚本目录。存档默认为“不导入”；选择一个存档后，该存档会被完整复制并重命名为 `world`。
7. 读取完成后，工具会结合 Minecraft 版本和已选模组声明的 Java 要求，扫描并推荐已安装的 Java。用户也可手动选择其他 `java.exe`。
8. 工具会自动刷新服务器核心。Fabric 可使用 Fabric Server 或受支持版本的 Cardboard；Forge 可使用 Forge Server、Mohist 或 CatServer；NeoForge 可使用 NeoForge Server；也可选择原版核心。只显示元数据确认支持当前游戏及加载器版本的核心。
9. 点击“开始准备”。工具会检查所选模组的依赖、冲突及明确的服务端阻断问题。“可能缺少必需前置模组”仅供参考，不会自动添加模组；遇到阻断问题时，可选择排除，也可选择保留并继续。
10. 填写输出名称并点击“生成服务器 ZIP”。未选择输出目录时会自动打开目录选择窗口；已有同名文件时会询问是否覆盖。
11. 导出前会询问是否同意 Minecraft EULA。选择“是”写入 `eula=true`，选择“否”写入 `eula=false`。
12. 工具将下载并安装服务器核心、复制或下载所选模组、复制配置和存档、生成启动脚本，最后输出一个 `.zip` 文件。

## 使用说明

模组适用性由模组元数据、平台信息、入口点、文件内容和已知客户端模组规则综合判断。该检查能够排除大量地图、界面、渲染、光影等客户端模组，但**不能替代实际启动测试**。用户手动勾选“不支持服务端”的模组后，仍可能导致服务器崩溃。

“全选”只会选择未禁用且未被判断为“不支持服务端”的模组，不代表强制包含所有文件。标记为“未知”的本地模组会默认保留，由用户自行确认其服务端兼容性。

整合包下载清单中的模组需要提供可验证的 HTTPS 下载地址和校验值。服务器核心或模组下载、校验、写入失败时，工具不会留下不完整的最终 ZIP。

原版核心不能加载任何模组或插件，选择时软件会再次警告。Cardboard、Mohist 和 CatServer 属于第三方混合核心，仅在其公开元数据确认支持当前版本时提供，实际兼容性仍由对应核心项目决定。

生成的 `start.bat` 与 `server-console.ps1` 作用相同。控制台会使用不同颜色突出普通日志、警告、错误和服务器启动成功状态。启动脚本会优先使用导出时选择的 Java；若在其他电脑运行且原路径不存在，则会尝试使用 `JAVA_HOME` 或系统 `PATH` 中的 Java。

选择 `eula=false` 时，服务器通常不会完成首次启动。用户应阅读并同意 Minecraft EULA 后再将其修改为 `true`。原始游戏目录或整合包不会被修改。




# 客户端整合包打包

## 使用流程

1. 选择 Minecraft 游戏目录或版本隔离实例。该模块**仅支持文件夹导入，不支持拖拽或导入已有整合包**。
2. 点击“读取内容”。若 `.minecraft` 根目录没有可读取的客户端内容，工具会提示重新选择 `.minecraft\versions\对应版本`；检测到多个标准版本 JSON 时会弹窗让用户选择。
3. 工具会读取 Minecraft 版本、加载器及加载器版本。以上信息由游戏目录决定，只读且不可修改。支持原版、Fabric、Forge、NeoForge 和 Quilt。
4. 工具将内容分为模组、材质包、光影包、地图与存档、Mod 与游戏配置、小地图/世界地图及其他 Mod 数据、游戏设置、服务器列表、截图、投影与结构、录像与回放等分类。
5. 未禁用的模组、材质包、光影包、配置目录和 `options.txt` 默认勾选；地图存档、小地图及其他 Mod 数据、服务器列表、截图、录像、快捷栏和命令历史等个人内容默认不勾选。父级复选框可控制整个分类。
6. 选择输出格式。Modrinth `.mrpack` 默认勾选，也可选择 CurseForge `.zip`，或同时选择两种格式。至少需要保留一种格式。
7. 输出名称会根据游戏目录名称和 Minecraft 版本自动生成；用户手动修改名称后，软件不会覆盖自定义内容。未选择输出目录时，点击生成会自动弹出目录选择窗口。
8. 点击“生成客户端整合包”。工具会计算文件哈希、匹配平台下载项、复制未识别内容、写入清单并压缩整合包。若同时选择两种格式，会分别生成 `.mrpack` 和 `.zip`。

## 使用说明

平台识别只使用**精确文件哈希**，不会根据文件名进行模糊搜索。Modrinth 会使用 SHA-1 查询并校验 SHA-512、文件大小及 HTTPS 下载地址；CurseForge 会校验文件指纹、项目类别、文件名、大小及可用哈希。

只有 `mods` 中的 JAR、`resourcepacks` 中的 ZIP 和 `shaderpacks` 中的 ZIP 会尝试写入平台下载清单。匹配失败、平台暂时无法访问、文件被修改、目录形式资源包及其他本地内容都会按原相对路径内嵌到 `overrides`，不会因为无法识别而直接丢弃。

客户端配置、地图、截图、服务器列表、小地图坐标和其他 Mod 数据可能包含个人信息或服务器地址，因此相关分类默认不勾选。导出前应检查所选内容，不要公开不希望分享的数据。

启动器账户、令牌、缓存、日志、崩溃报告、运行库、原生库和启动器配置等内容会被排除，不会作为普通客户端内容提供导出。符号链接或重解析点也不会被打包。

同时生成两种格式时，两项任务彼此独立：一种格式失败不一定影响另一种格式。软件会列出成功生成的文件及失败原因；构建取消或失败时不会留下未完成的最终压缩包。

生成标准整合包不代表其中所有文件均允许公开再分发。发布前仍需由用户确认模组、材质包、光影包、地图及其他资源各自的授权条款。原始游戏目录不会被修改。
